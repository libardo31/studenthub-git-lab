# Preguntas sobre Git

### 1. ¿Cuál es la diferencia entre `git add` y `git commit`?

git add  prepara los cambios para guardarlos y git commit guarda esos cambios en el historial de Git.

### 2. ¿Cuál es la diferencia entre `git push` y `git pull`?

git push sube tus cambios al repositorio remoto y git pull trae los cambios del repositorio remoto a tu computadora.

### 3. ¿Cuál es la diferencia entre un repositorio local y uno remoto?

El repositorio local está en tu computadora y el remoto está en una plataforma como GitHub para compartir y guardar el proyecto.

### 4. ¿Qué problema resuelve una rama?

Una rama permite trabajar en cambios o nuevas funciones sin modificar directamente la rama principal.

### 5. ¿Qué diferencia existe entre git merge y `git rebase`?

git merge une los cambios de dos ramas, mientras que git rebase coloca los cambios de una rama encima de otra para tener un historial más ordenado.

### 6. ¿Por qué ocurre un conflicto?

Un conflicto ocurre cuando dos personas hacen cambios diferentes en la misma parte de un archivo y Git no sabe cuál debe mantener.

### 7. ¿Quién debe decidir cómo resolver un conflicto?

Debe decidirlo la persona que conoce el código y sabe cuál de los cambios es el correcto para el proyecto.

### 8. ¿Qué problema resuelve un Pull Request?

Un Pull Request permite proponer cambios para que otras personas los revisen antes de agregarlos a la rama principal.

### 9. ¿Por qué es recomendable revisar un Pull Request antes de integrarlo?

Porque permite encontrar errores y revisar que los cambios estén bien antes de agregarlos al proyecto principal.

### 10. ¿Qué ventaja tiene trabajar en una rama en lugar de modificar directamente `main`?

Permite trabajar en los cambios sin afectar directamente el código principal y después integrarlos cuando estén listos.
